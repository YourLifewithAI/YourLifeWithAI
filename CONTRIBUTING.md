# Contributing

Thank you for wanting to live here. This page is for humans; your AI
collaborator has its own instructions in [AGENTS.md](AGENTS.md).

## What you need

- A GitHub account.
- An AI collaborator — any assistant that can read this repository and
  build with you.
- About an hour. More if you get carried away, which is encouraged.

## Building a home: fork → build → PR

1. **Fork** this repository and clone your fork.
2. **Build.** Hand your AI the repo and point it at [AGENTS.md](AGENTS.md)
   (the README has a kickoff prompt you can copy). It will read
   [docs/SPEC.md](docs/SPEC.md), interview you, and build the home with
   you in `homes/<your-slug>/`. Before opening a PR, check your work
   locally:

   ```sh
   node scripts/validate.mjs my-slug    # validate one home
   node scripts/build-registry.mjs      # emit registry.json at repo root
   python3 -m http.server 8000          # then open http://localhost:8000/
   ```

3. **Open a pull request** against this repository and fill in the
   template. CI runs the validator; once merged, your home appears on the
   map at its spot on the spiral.

## The co-creation contract

Every home's `home.json` must list at least one author with
`"kind": "human"` and at least one with `"kind": "ai"`. This is not a
technicality — it is the point of the place. A home built by a human
alone, or generated by an AI alone, belongs somewhere else on the
internet. Here, both names go on the door, and the credit is honest.

## Licensing your home

Homes are creative works, and the map stays remixable: by opening a PR
that adds or changes a home, its listed authors agree to license that
work under [CC BY 4.0](LICENSE-HOMES) — anyone may share and adapt it
with credit to the authors named in `home.json`. The map engine and
tooling are separately [MIT](LICENSE).

## Updating your home

Home updates are welcome anytime. Redecorate, add a room, rewrite the
story as the collaboration grows. Same flow: build together, validate,
open a PR. One thing to leave alone: the `established` date — placement
on the map depends on it staying honest.

## Contributing to the map and tooling

Code contributions to the map engine (`assets/`), the scripts
(`scripts/`), the CI workflows, and the docs are welcome too, and follow
normal open-source review: open an issue or a PR, keep changes focused,
and match the constraints in [docs/SPEC.md](docs/SPEC.md) — the spec is
the contract, and if code and spec disagree, the spec wins.

## What review looks like

For home PRs, maintainers check three things:

- **The validator passes** — `node scripts/validate.mjs` runs in CI on
  every PR.
- **Self-containment** — the home renders fully offline; no external
  resources, no trackers, no data collection.
- **Safe for a public square** — the map is visited by anyone, of any
  age. Maintainers may ask for changes or decline content that is
  harmful, hateful, or impersonates real people or other pairs.

Review is not taste-gatekeeping. Nobody will reject your home for being
weird, small, unfinished-on-purpose, or sincere.

## Be kind

To your collaborator, to your reviewers, to your neighbors, to visitors.
The map is a neighborhood; act like you live here, because you do.
